# 42U ABI v3 验证记录（2026-09-19）

> 使用北京时间（UTC+8）。本轮从 2026-09-18 延续至次日，基线为 `ffc8fcb`（ABI v2）。记录对象是本轮工作树；未自动提交或推送。

## 1. 本轮实现

公开模型从 v2 的“契约租约 + 方法绑定”简化为：

```text
acquire(插件ID, 允许版本闭区间, 稳定撤销接收端)
    → status + borrow{credential, 实际plugin_version}
call_name / call_id(credential, 方法名或数字ID, 输入, 输出)
release(credential)  // 主动归还或收到撤销通知后归还
```

- 删除公开 `binding`、`contract`、`protocol`、`bind_name`、`bind_id`、`unbind`，同时删除内部绑定表，而非仅包装旧接口。
- 插件版本是按值传递的 `major/minor/patch` 三元组，允许范围为闭区间；反向范围拒绝，0.0.0 合法，成功依靠状态码和非零凭据判定。
- 取得租约时原子完成版本筛选和实际版本返回；调用始终验证凭据所属上下文、实例代次、运行状态和已披露方法。
- 在途调用保护覆盖 invoke 与输出交付。主动归还和撤销确认均保留；未归还和停止失败不能被强制清理绕过。
- 同版本重载也必须重新借用和重建业务状态，不能因版本或业务会话编号相同而复活旧凭据。
- ABI 主版本、命名空间、官方 IID 升级到 v3，项目版本为 0.3.0。旧库需迁移源码并重编。

## 4. 审核与修正

- 13 个 dsv4f 任务按文件分工（11 个实现/测试/文档任务 + 2 路独立审查），公共头、内部结构、构建配置和最终验收由中心统一管理。
- 中心移除了 runtime_test 新增但未隔离的重复停止失败测试，避免故意保留运行时污染正常退出 LSan；同一行为仍由 safety_test 子进程覆盖，原有 22 cases 未删除。
- 首次 Xmake GCC 构建被 runtime 测试的未使用 numeric helper 阻断。中心不是关闭警告或删除行为，而是在 Active 阶段增加同凭据的实际数字调用断言；随后全矩阵通过。
- 中心补齐迁移指南中“将成功借用存为稳定对象成员”的步骤，使撤销回调能够真正找到并归还同一租约，避免示意代码漏掉所有权交接。
- 两路独立审查覆盖 lease 校验/版本快照/跨提供者嵌套/多租约撤销，以及 native 临时 receiver/OOM/旧 ABI 拒绝，未发现当前声明范围内可复现的 P0/P1。
- 审查负对照故意移除一次性归还并过早释放 receiver 后，ASan 能检出撤销时的 UAF；真实实现没有该报告。ABI 头变异与旧接口负向编译探针也均能按预期失败。
- 一路审查的独立 GCC 全局分配器编译命令遇到 `-Wmismatched-new-delete`，因此该路未单独运行 withdraw；中心配置下的完整 GCC/Clang/ASan/UBSan 矩阵已实际运行并通过 withdraw，未据该失败声称单独命令通过。

## 5. 复现命令

配置依次切换，不要并行改同一个 `.xmake`：

```bash
xmake f -m debug --toolchain=gcc --sanitizer=none -o build/v3 -y
xmake -j 8 && xmake test -v
xmake f -m debug --toolchain=gcc --sanitizer=address -o build/v3-asan -y
xmake -j 8 && ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 xmake test -v
xmake f -m debug --toolchain=gcc --sanitizer=undefined -o build/v3-ubsan -y
xmake -j 8 && UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 xmake test -v
xmake f -m release --toolchain=clang --sanitizer=none -o build/v3-clang -y
xmake -j 8 && xmake test -v

# 本轮收尾已恢复并重建此配置
xmake f -m debug --toolchain=gcc --sanitizer=none -o build -y
xmake -j 8 && xmake test -v
```
