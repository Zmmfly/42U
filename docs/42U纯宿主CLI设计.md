# 42U 纯宿主 CLI 设计

> 文档版本：0.1（设计草案）
>
> 状态：尚未实现。本文描述 ABI v3 之上的独立 CLI 扩展方向，不改变现行 `u42::abi::v3` 基础接口、项目版本或现有 `42uhost` 行为。
>
> 范围：可信本地动态库插件的声明式 CLI 命令面、根级配置参数、发现流程、配置快照和命令执行边界。
>
> 审核：已完成一次独立架构审核；CLI11 相关结论基于对 CLI11 2.x 动态 option/subcommand 行为的检查。本文不声称已完成实现或测试。

## 1. 定位

42U 的定位是**纯宿主**：

```text
42U core:
    插件发现、生命周期、配置快照、租约调用网关

CLI manifest extension:
    插件声明根参数、子命令、局部参数和 handler 绑定

42uhost:
    用 CLI11 动态组装受限 CLI 语法
```

宿主自身不提供业务命令。除基础设施所需的 `--help` 与 `--version` 外，业务根参数、子命令、命令参数和命令语义均由可信插件声明。插件不直接注册 CLI11 回调，也不把 CLI11 类型、option 指针或 C++ 回调对象传入 ABI；CLI11 只是 `42uhost` 前端的实现依赖。

### 1.1 职责划分

| 参与方 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 宿主 | 插件目录发现、manifest 读取与复制、命令面冲突校验、CLI 解析、配置快照、插件生命周期、handler 调用、进程退出码 | 解释业务参数含义、实现业务命令、把一个插件的配置广播给其他插件 |
| CLI manifest 扩展 | 声明根参数、子命令、局部参数、类型与数量约束、默认值和 handler 方法绑定 | 执行命令、注册解析器回调、越过宿主调用插件 |
| 插件 | 消费自身配置、发布 handler 方法、执行业务逻辑、返回结果与业务失败信息 | 声明宿主保留参数、修改本次插件集合、直接解析进程 argv |
| CLI11 | 在 `42uhost` 内动态构建 option/subcommand 并保存原始解析结果 | 成为 42U ABI 的一部分或定义 42U 协议语义 |

## 2. 目标与边界

| 纳入第一版 | 暂不纳入第一版 |
| --- | --- |
| 独立版本化 CLI manifest 导出 | 修改 ABI v3 的 `plug_desc`、既有虚接口或既有 vtable |
| 插件声明根级配置参数 | 根级 required 参数 |
| 插件声明一级子命令与局部参数 | 嵌套命令、多插件共同扩展同一父命令 |
| 每次调用最多执行一个短时长命令 | 常驻 `serve` 类长任务执行协议 |
| 全量启动已发现插件 | 按命令或依赖闭包按需启动 |
| long option 与固定位置参数 | short option、选项缩写、`--cmd.opt` 点号形式 |
| CLI 显式值覆盖插件默认值 | 配置文件、环境变量和多来源合并优先级 |
| `iconfig` 实例存活期只读配置 | 运行中修改配置、热更新或跨实例状态迁移 |

第一版必须保持现有运行模型：可信、同进程、单控制线程、同步动态调用。任何需要跨线程回调宿主、异步任务取消或流式输出的能力都先扩展协议，不把同步 handler 改成无限阻塞。

## 3. CLI 语法

### 3.1 语法形态

```text
42u --version
42u --help
42u [plugin-declared-root-options] <command> [command-options]
```

示例：

```bash
# --log-level 由日志持久化插件声明；serve 与 --port 由服务插件声明。
42u --log-level debug serve --port 8080

# 另一个插件也可以声明自己的根级配置。
42u --log-level debug --metrics-enable serve --port 8080

# 不同子命令的局部参数可以同名。
42u serve --port 8080
42u proxy --port 9090
```

`--log-level` 虽然出现在根命令上，但归日志插件所有。宿主只把值写入该插件的配置快照，不把它自动广播给其他插件。其他插件若需要日志行为，应通过日志插件提供的能力或服务协作。

### 3.2 宿主保留项

第一版保留：

- 根级 `--help`；
- 根级 `--version`；
- 各子命令作用域内的 `--help`。

插件不得声明 `help`、`version` 为命令名，也不得声明 `--help`、`--version` 为参数名。插件目录选择不是业务 CLI 参数；第一版使用：

1. 若设置 `U42_PLUGIN_DIR`，使用该环境变量指定的唯一目录；
2. 否则使用真实可执行文件旁的 `plugins` 目录。

`U42_PLUGIN_DIR` 必须是单个有效目录路径。CLI 参数不得改变本次已经完成发现的插件集合。

### 3.3 作用域规则

1. 根级参数必须出现在子命令之前。
2. 子命令参数必须出现在所属子命令之后。
3. 根级参数全局唯一；两个插件声明同名根参数时发现失败。
4. 顶层子命令名全局唯一；两个插件声明同名命令时发现失败。
5. 根级参数名不得与任何子命令局部参数名相同，禁止局部遮蔽。
6. 不同子命令的局部参数可以同名。
7. 一次调用最多选择一个子命令。
8. 仅提供根参数而没有子命令时返回用户输入错误；第一版不引入默认命令。
9. 第一版只支持 long option，不支持 short option 和选项缩写。
10. 未被选择命令的参数不参与 required 校验。

### 3.4 受限 CLI11 语法

CLI11 允许的语法多于 42U 协议应接受的语法。因此 CLI11 是实现工具，不是 42U CLI 语义的规范来源。前端必须显式限制：

- 拒绝 `--serve.port=8080` 这类点号形式；
- 拒绝 `++` 或 `--` 返回父级解析的形式；
- 拒绝选项前缀匹配；
- 拒绝额外位置参数；
- 保持 `require_subcommand(1, 1)`；
- 根据宿主自身的 manifest 校验禁止根/局部同名。

不能只依赖关闭 CLI11 fallthrough；测试必须覆盖 CLI11 的额外语法负例。

### 3.5 空值语义

值参数使用以下形式表示显式空字符串：

```bash
42u --label= serve
42u --label "" serve
```

显式空值与“未提供”不同。未提供时使用插件默认值；提供空字符串时配置快照必须记录来源为 CLI 且值为空。manifest 校验和 `iconfig` 查询不得把两者混同。

## 4. CLI manifest 扩展

### 4.1 扩展路线

基础 ABI 仍为 v3，不直接升级 ABI v4。新增一个独立版本化导出，例如概念性的：

```cpp
extern "C" u42::status U42_CALL u42_get_cli_manifest(...)
```

具体签名、结构尺寸和 IID 在实现前另行冻结。该导出与 `u42_get_factory` 一样使用 C 链接入口，但拥有独立的 manifest 主版本。扩展规则：

1. 没有 manifest 导出的 v3 插件仍可加载，只是不贡献 CLI 命令面。
2. manifest 导出存在但版本不支持时拒绝加载，不做静式忽略。
3. manifest 内容非法、含未知类型或含未知 flags 时拒绝加载。
4. manifest 在实例创建前返回，宿主必须深拷贝所有字符串和数组。
5. manifest 是不可变声明；实例运行期间不得改变本次命令面。
6. handler 只能绑定所属插件稍后发布的方法，不得绑定函数指针或其他插件的方法。

### 4.2 声明身份

内部身份使用稳定 ID，而不是用户可见名称：

```text
root parameter: (plug_id, root_param_id)
command:        (plug_id, command_id)
command param:  (plug_id, command_id, param_id)
```

用户可见名称可以因本地化或产品需要调整；稳定 ID 参与 ABI 兼容、配置键和 payload 字段。可见名称仍需满足有限字符集并受长度限制。

### 4.3 根级参数

根级参数声明至少包含：

- stable `root_param_id`；
- 可见 long option 名；
- help 与 value name；
- 类型与值约束；
- 默认值或明确无默认；
- 出现次数策略；
- 是否敏感值。

根级参数只进入配置快照，不绑定业务 handler，也不触发命令执行。第一版不开放根级 required，避免一个插件使所有命令不可用。

### 4.4 子命令

子命令声明至少包含：

- stable `command_id`；
- 可见命令名；
- help；
- 参数数组；
- handler 绑定的本插件 `method_id`。

局部参数声明至少包含：

- stable `param_id`；
- 可见 long option 名或固定位置参数序号；
- help 与 value name；
- 类型、默认值、枚举或范围；
- required、repeatable、flag 等语义；
- payload 字段或显式 `config_key` 映射。

局部参数默认进入 handler payload。只有显式声明 `config_key` 时才写入配置快照，且仅在该命令被选择时注入。

### 4.5 第一版类型与重复策略

第一版建议只提供：

- 单值 TEXT；
- 零参数 FLAG；
- 固定位置 TEXT；
- 可重复 TEXT，每次出现提供一个值并形成列表。

数值、路径、枚举和范围可以先作为宿主侧词法校验，最终 payload 仍保持确定性字符串表示，由插件做语义校验。避免第一版把完整 schema 系统引入 ABI。

## 5. 配置快照与 `iconfig`

配置在第一次 `init()` 前冻结，实例存活期间只读。新增 `iconfig` 服务时使用新的官方 IID，不修改既有 `ievents`、`icaps`、`icalls` 或 `idiag`。

概念能力：

```cpp
struct iconfig {
    virtual status U42_CALL entries(...) noexcept = 0;
    virtual status U42_CALL get(const char* key, bytes* out) noexcept = 0;
};
```

最终签名以实现时的 ABI 扩展头文件为准。语义约束：

1. 每个插件只能查询自己的配置；
2. 配置值由宿主持有，查询返回的视图只在本次调用内有效；
3. 插件需要跨调用保存时必须复制；
4. 配置条目保留存在性、类型、值和来源；
5. 来源至少区分插件默认值与 CLI 显式值；
6. `init()`、`start()` 和 handler 内都可以读取，但不得修改；
7. 根级参数和显式映射的局部参数都通过同一服务读取；
8. 服务保持前端中立，嵌入式宿主以后可以用同一机制注入配置。

第一版合并规则只有：

```text
CLI explicit value > plugin declared default
```

配置文件与环境变量合并策略后续另行设计。

## 6. Handler payload

CLI 解析结果必须转换为稳定的 handler 请求字节，再走现有宿主动态调用路径。建议第一版使用确定性 JSON 对象：

```json
{
  "port": "8080",
  "labels": ["a", "b"],
  "verbose": true
}
```

规则：

- 对象字段名使用 `param_id`，不使用用户可见选项名；
- 单值 TEXT 与列表元素使用 JSON 字符串；
- FLAG 使用 JSON boolean；
- 数组保持 CLI 出现顺序；
- 宿主只做确定性序列化，不解析或改写插件返回的业务结果；
- 插件仍负责最终类型、范围和业务校验；
- 输入和输出继续受 `host_options::payload_limit` 与 `output_limit` 约束。

handler 绑定是 `method_id`。宿主在插件 Active 并发布能力后验证绑定存在，再通过现有租约调用保护执行；不得绕过 `icalls` / `iinvoke` 直接调用插件函数。

## 7. 发现与生命周期

### 7.1 发现阶段

现有 `host::add()` 与 `host::boot()` 会创建并启动实例，不能直接作为 manifest discovery 使用。新增发现流程必须独立持有库映射：

```text
确定插件目录
    ↓
扫描候选动态库
    ↓
dlopen、协商基础 ABI v3、读取工厂描述
    ↓
读取并深拷贝 CLI manifest
    ↓
保持库映射打开，形成 discovery 记录
    ↓
校验插件 ID、manifest、保留名和全局命令面冲突
    ↓
构建 CLI11 并解析 argv
    ↓
生成只读配置快照
    ↓
把库映射和工厂所有权安全移交给运行时
    ↓
create()
    ↓
init(ctx)
    ↓
全部 init 完成后 start()
    ↓
执行选定 handler
    ↓
shutdown()
```

发现记录必须同时拥有 DSO 映射、工厂和复制后的描述。不得发现后关闭库再重新加载，也不得让前端局部对象先卸载仍被工厂或实例引用的 DSO。停止失败时必须沿用现有资源保留策略，不能因 CLI 流程而强制释放不安全映射。

### 7.2 生命周期保证

- `--version` 不发现插件、不创建实例；
- 完整 `--help` 需要读取 manifest，但不创建、初始化或启动实例；
- manifest 声明错误、命令面冲突和 argv 解析错误不创建实例；
- 配置必须在第一次 `init()` 前冻结；
- 保持全部 `init()` 完成后再 `start()`；
- 第一版全量启动所有已发现插件；
- 未被选择命令的插件 `start()` 只能准备公共能力，不得执行业务动作；
- shutdown 失败时保留必要实例与库映射，并以非零退出码报告。

加载动态库和调用描述入口本身可能执行插件代码。即使尚未 `create()`，DSO 构造函数与描述函数也可能运行。因此该 CLI 设计仍只适用于可信本地插件；描述入口不得执行业务初始化属于协作契约，不是沙箱隔离保证。

## 8. 执行与退出语义

### 8.1 命令执行

第一版只支持有限时长的同步单命令：

```text
解析成功
    ↓
全量 create/init/start
    ↓
验证 handler method_id 已发布
    ↓
构造 payload
    ↓
经宿主调用网关执行
    ↓
收集完整结果或失败状态
    ↓
shutdown
```

handler 不得无限阻塞。当前控制线程调用模型下，永久运行的服务会阻止事件派发、租约撤销和正常关停。`serve` 只是语法示例；若要正式交付常驻命令，必须先增加执行任务协议：

```text
execute -> 已完成或 task_id
status(task_id) -> 短时返回
cancel(task_id) -> 短时返回
宿主循环 -> poll、信号处理、取消和关停
```

插件私有工作线程不得回调宿主接口。`stop()` 成功前必须结束相关私有工作线程。

### 8.2 流与退出码

42U 自行定义进程语义，不继承 CLI11 或 ABI 状态码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 发现、声明、启动、业务执行或清理失败 |
| 2 | 用户输入错误 |

规则：

- CLI11 的内部错误码必须统一映射为 `1` 或 `2`；
- `abi::status` 表示调用机制结果，不是业务退出码；
- 第一版可规定 handler 返回 `ok` 时进程退出码为 0，非 `ok` 为 1；
- 业务成功但 shutdown 失败时返回非零；
- 业务失败与清理失败同时存在时保留主错误并报告清理错误；
- stdout 用于版本、帮助和命令结果；
- stderr 用于诊断；
- 命令结果必须完整收集后输出，不提供实时流式输出。

## 9. 兼容性

### 9.1 ABI 兼容

本设计不修改 ABI v3 的基础结构、虚接口槽位或官方既有服务 IID。CLI manifest 与 `iconfig` 是版本化扩展：

| 场景 | 行为 |
| --- | --- |
| 新宿主加载旧 v3 插件，无 manifest 导出 | 正常加载，不贡献 CLI 命令面 |
| 新宿主遇到不支持的 manifest 版本 | 发现失败，不创建实例 |
| 使用 `iconfig` 的插件运行在旧宿主 | 由插件决定降级或初始化失败；不承诺可用 |
| 旧插件声明与插件间现有能力 | 继续走 ABI v3 租约调用 |

新增官方 IID 时必须使用新的 IID 值，不得复用或扩展既有接口槽位。

### 9.2 CLI11 依赖

CLI11 只允许作为 `42uhost` 的依赖：

```text
42u static library       no CLI11
plugin SDK and ABI       no CLI11
fixtures and examples    no CLI11
42uhost                  CLI11
```

CLI11 版本应锁定，所有受限语法负例纳入持久测试。CLI11 升级不得隐式改变 42U 用户可见协议。

## 10. 验收标准

第一版实现必须至少覆盖：

| 类别 | 验证 |
| --- | --- |
| 发现边界 | `--version` 不加载插件；帮助和解析错误不 create/init/start |
| DSO 所有权 | discovery 到运行时移交后库映射不提前释放；停止失败时保留资源 |
| 命令面冲突 | 保留名、根参数重复、命令重复、根/局部遮蔽均失败并给出双方插件与声明 ID |
| 受限语法 | 点号形式、父级返回形式、前缀匹配、额外参数和重复选择均拒绝 |
| 根参数 | CLI 值写入所属插件配置，不广播给其他插件 |
| 空值 | 显式空值、未提供和默认值可区分 |
| 局部参数 | 未选命令 required 不生效；局部参数默认进入 payload |
| 配置生命周期 | 第一次 init 前冻结；实例存活期只读；插件不能查询他人配置 |
| handler 保护 | 绑定缺失失败；只能调用所属插件已发布 method；仍经宿主调用网关 |
| 执行边界 | 短命令成功/失败；业务失败叠加清理失败时退出码和诊断正确 |
| 兼容性 | 无 manifest 的旧 v3 插件正常加载；不支持或非法 manifest 拒绝加载 |

## 11. 实施顺序

1. 冻结 manifest v1 数据结构、导出签名、长度限制和 `iconfig` IID；
2. 实现独立 discovery 记录与 DSO 所有权移交；
3. 实现配置快照和 `iconfig`；
4. 引入 CLI11 并实现受限语法与动态命令面；
5. 迁移或移除现有 `--list`、`--call`、`--call-id` 管理动作；
6. 补齐发现、解析、配置、调用、退出码和兼容性测试；
7. 常驻命令另立任务协议设计，不通过阻塞同步 handler 实现。

在上述项完成前，本文只是设计规范草案，不作为当前源码已支持该行为的验证依据。
