# 42U ABI v2 迁移指南

> 适用对象：从 ABI v1 迁移到 v2 的插件作者、消费者作者与使用 `42uhost` 的管理人员。
>
> 本指南只描述已经存在的 v2 API；未出现在 `inc/42u/abi.hpp`、`inc/42u/host.hpp`、`inc/42u/sdk.hpp` 中的接口不在此虚构。配套阅读：[设计主文档](42U插件框架设计.md)。

## 1. 为什么迁移

一句话：v1 允许插件之间借用 **类型化业务虚接口** 并直接调用；v2 把插件间协作收敛为 **invoke-only + 可撤销实例租约**。消费者不再持有任何提供者的业务类或接口指针，所有业务流量都走：

```text
消费者 → 宿主 icalls → 提供者 iinvoke
```

由此带来三处硬性变化：

- 借用结果 `borrow` 只含一个不透明凭据 `token`，不再有 `void* ptr`。
- 绑定方法必须提供租约凭据，不能直接按 `plug_id` 绑定或调用。
- 业务协议用 `contract{ id, major, minor }` 表达，与插件发布版本、宿主内部实例代次互不推断。

## 2. 兼容性边界（先读这一段）

- v2 宿主向入口请求主版本 `2`；仅支持主版本 `1` 的旧动态库必须返回 `unsupported`，宿主**明确拒绝加载**，不会把旧工厂当作新接口使用。
- v2 不保留 v1 的源兼容别名，也不在旧 `iid` 下提供变签名；需要先按本指南迁移插件源码，再重新编译。
- 入口名仍为 `u42_get_factory`，只在主版本上区分。
- 官方服务 `iid.high` 随代际变化，v1 与 v2 的跨界结构布局不同，不能混用。
- 上述拒绝依赖入口正确检查 major。谎报版本或返回错误类型工厂属于插件违反契约，宿主不保证能安全识别其虚表；这不是不可信插件沙箱。

## 3. 旧 / 新小段对照

下列代码用于比较 API 形状，省略了状态检查，不应整段直接拼接为程序。实际代码必须检查 acquire/bind/call/release 的返回值，并保证撤销接收端活到租约成功归还。

### 3.1 命名空间与 ABI 主版本

| | 旧（v1） | 新（v2） |
| --- | --- | --- |
| 命名空间 | `u42::abi::v1` | `u42::abi::v2` |
| `abi_major` | `1` | `2` |

```cpp
// 旧
namespace a = u42::abi::v1;
// 新
namespace a = u42::abi::v2;
```

### 3.2 官方 IID 高半部

| | 旧（v1） | 新（v2） |
| --- | --- | --- |
| `iid.high` | `0x3432555f41424931` | `0x3432555f41424932` |
| `iid.low` | 1..5 | 1..5（不变） |

`events_iid`、`caps_iid`、`calls_iid`、`diag_iid`、`invoke_iid` 名称不变，值随高半部更新。

### 3.3 能力披露：接口列表 → 一份业务协议 + 多方法

| | 旧（v1 `caps_desc`） | 新（v2 `caps_desc`） |
| --- | --- | --- |
| 字段 | `struct_size`、`interface_count`、`interfaces`、`method_count`、`methods` | `struct_size`、`method_count`、`methods`、`protocol` |
| 接口列表 | `const iid* interfaces` | 已删除 |
| 业务协议 | 无 | `contract protocol` |

规则：

- 一个实例只披露**一份** `protocol`，其下可以有多个方法。
- 非空 `methods` 必须披露有效 `protocol`（满足 `valid_contract`）。
- 全 0 空 `protocol` 仅在 `methods` 为空时合法，表示无业务能力，不可被借用。
- 有效 `protocol` 配空 `methods` 可被合法借用其生命周期。

```cpp
// v1：共享头声明一个业务虚接口
constexpr a::iid echo_iid{0x6563686f34325531ULL, 1};
struct iecho { virtual a::status U42_CALL echo(a::bytes, a::iwriter*) noexcept = 0; };
// v2：共享头只声明数据契约常量与方法号，不声明业务虚类
constexpr a::contract echo_contract{{0x6563686f34325532ULL, 1}, 1, 0};
constexpr a::method_id echo_method_id = 1;
const a::method_desc methods[]{{echo_method_id, "echo", "...", "{}", "{}"}};
const a::caps_desc caps{sizeof(a::caps_desc), 1, methods, echo_contract};
```

### 3.4 借用：`iid` 指针 → 显式 `contract`

| | 旧（v1 `icaps::acquire`） | 新（v2 `icaps::acquire`） |
| --- | --- | --- |
| 签名 | `acquire(const char* plug_id, const iid* type, irevoker*, borrow*)` | `acquire(const char* plug_id, const contract* required, irevoker*, borrow*)` |
| 匹配 | 精确 `iid` | `compatible_contract(offered, required)`：`id` 相同、`major` 相同、`minor` 满足 |
| `borrow` | `{ void* ptr; token credential; }` | `{ token credential; }`（无指针） |

```cpp
// 旧：拿到接口指针并直接调用
a::borrow b{};
caps->acquire("com.example.echo", &example::echo_iid, &revoker, &b);
// b.ptr 可直接调用

// 新：只拿凭据，没有指针可用
a::borrow b{};
caps->acquire("com.example.echo", &example::echo_contract, &revoker, &b);
```

### 3.5 绑定：按 `plug_id` → 按租约凭据

| | 旧（v1） | 新（v2） |
| --- | --- | --- |
| `icalls::bind_name` | `bind_name(const char* plug_id, const char* name, binding*)` | `bind_name(token credential, const char* name, binding*)` |
| `icalls::bind_id` | `bind_id(const char* plug_id, method_id id, binding*)` | `bind_id(token credential, method_id id, binding*)` |

没有不要求租约的插件侧绑定或调用捷径。

```cpp
// 旧
a::binding binding{};
calls->bind_name("com.example.echo", "echo", &binding);
// 新
a::binding binding{};
calls->bind_name(b.credential, "echo", &binding);
```

### 3.6 解绑与归还：`unbind` 不解锁

| 操作 | 行为 |
| --- | --- |
| `unbind(binding)` | 只删除该绑定；不归还租约、不解除卸载锁 |
| `release(credential)` | 解除租约锁，并删除该租约及其所有绑定；此后旧绑定的 `call`/`unbind` 返回 `stale` |
| 在途调用 | 覆盖提供者 `invoke` 与输出交付；期间 `release` 返回 `busy` 并保留租约 |

### 3.7 SDK 租约：模板 `sdk::lease<T>` → 非模板 token 租约

| | 旧（v1） | 新（v2） |
| --- | --- | --- |
| 类型 | `template <class T> class lease` | `class lease`（非模板） |
| 保存内容 | 业务接口指针 + credential，另持宿主 `icaps*` | credential + 用于归还的宿主 `icaps*`；不持任何提供者指针 |
| 取指针 | `get()` / `operator->` | 已删除 |
| 其余 | `reset()`、`matches()`、move、`bool` | `reset()`、`matches()`、`credential()`、move、`bool` |

```cpp
// 旧
u42::sdk::lease<example::iecho> lease{caps, b};
return lease->echo(args, writer);
// 新
u42::sdk::lease lease{caps, b};
a::binding binding{};
calls->bind_name(lease.credential(), "echo", &binding);
```

### 3.8 宿主管理端 API

| | 旧（v1 `u42::host`） | 新（v2 `u42::host`） |
| --- | --- | --- |
| 协议发现 | 无 | `protocol(plug_id, contract*)` |
| 借用 / 归还 | 无 | `acquire(plug_id, required, irevoker*, borrow*)` / `release(token)` |
| 绑定 | `bind(plug_id, method, binding*)` | `bind(token credential, method, binding*)` |
| 便捷调用 | `call(plug_id, method, bytes, string*)` | 已删除 |
| 便捷调用（新） | 无 | `call(plug_id, required, method, bytes, string*)` |

新便捷调用在一次控制线程操作内完成 acquire → bind → call → unbind → release，不保留提供者会话；需要跨调用保持状态时应显式持有租约。CLI 语法不变，但每次调用前都会先用 `host::protocol()` 发现一次当前协议，这是管理端的一次性当前协议调用。

### 3.9 重载：旧指针失效 → 旧租约 / 绑定 `stale`

- v1：重载后旧接口指针失效。
- v2：重载后旧租约与旧绑定永不自动跟随；**即使协议完全相同**，也必须重新发现、重新验证 `compatible_contract`、重新借用并重建会话 / 缓存 / 状态。旧租约或旧绑定调用返回 `stale`。

### 3.10 撤销回调：清指针 → 归还凭据

- v1：`on_revoke` 停止使用接口指针。
- v2：`on_revoke(token)` 先停止本代业务、删除本代绑定与会话 / 缓存，再归还凭据。若 `release` 返回可重试状态（例如在途调用导致 `busy`、或 `failed`/`wrong_thread`），必须保留凭据并在后续通知或 `stop()` 中重试，不能丢弃凭据伪造归还。

## 4. 新手流程图

### 4.1 正常借用与调用

```text
消费者 init：query(&caps_iid, ...) 、query(&calls_iid, ...)
        │
        ├─ watch() 订阅协议快照（排队交付，无内联回调）
        │
   on_capability：读 cap_event.capabilities.protocol
        │
   compatible_contract(offered, required)?
        │ 否 → 记录变化，继续等待
        │ 是
        ▼
   acquire(plug_id, &required, &stable_revoker, &borrow)
        │  ok（Initialized 也可借用，但不能 call）
        ▼
   bind_name(credential, "echo", &binding)  // Initialized 也可绑定，不执行业务
        │
   start 成功返回宿主 → Active             // start() 调用内部仍为 Starting
        │
   call(binding, args, &writer)     // 消费者 → 宿主 icalls → 提供者 iinvoke
        │
   unbind(binding)                  // 只删绑定，不解锁
        │
   release(credential)              // 才解除租约锁；在途调用期间返回 busy
```

### 4.2 撤销路径

```text
宿主 unload 或重载
        │
   irevoker::on_revoke(token)
        │  1) 停止本代业务
        │  2) 删除本代 binding / 会话 / 缓存
        │  3) release(token)
        │
   release 返回 ok/stale → 清空本地凭据
   release 返回 busy/failed/wrong_thread → 保留凭据，后续通知或 stop() 重试
        │
   租约未归还前 → 卸载被拒绝（隔离，不强行拆解）
```

## 5. 迁移检查清单

- [ ] 所有 `u42::abi::v1` 改为 `u42::abi::v2`，入口主版本传 `2`。
- [ ] `caps_desc` 去掉 `interfaces`/`interface_count`，改为一份 `protocol` + 方法集合。
- [ ] 为业务方法定义 `contract`（`id`/`major`/`minor`）与方法号常量，放在只含数据的共享头。
- [ ] 消费者用 `compatible_contract(offered, required)` 判断接受，不读插件发布版本。
- [ ] 消费者不再保存任何提供者接口指针；只保存租约凭据与绑定。
- [ ] `bind_name`/`bind_id` 改为传凭据；删除所有按 `plug_id` 直接绑定的代码。
- [ ] `sdk::lease<T>` 改为非模板 `sdk::lease`，删除 `get()`/`operator->` 调用。
- [ ] `on_revoke` 中先停业务、清本代状态，再归还凭据，失败时重试。
- [ ] 重载后即使协议相同，也重新借用并重建状态。
- [ ] 卸载失败或停止失败时不删除租约记录、不伪造归还。
- [ ] 确认业务路径确实是 `消费者 → 宿主 icalls → 提供者 iinvoke`，没有直接跨插件调用。

## 6. 不要夸大 v2 的能力

- **同进程治理**：不承诺内存隔离、崩溃隔离、强制超时或强杀，不支持不可信插件。
- **内存不足**：宿主只做尽力清理，可能留下 Created 或隔离记录，不保证全部回滚，也不夸大清理成功率。
- **管理端 CLI**：每次命令显式发现一次当前协议并按结果调用，不代表长期消费者会自动接受协议升级，也不校验 JSON/schema。
