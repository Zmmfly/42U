# 42U ABI v3 迁移指南

> 本文面向从 ABI v2 迁移到 **ABI v3** 的插件与宿主调用方。
>
> v3 的核心变化只有一句话：**不再有业务协议（contract）、绑定（binding）和 bind/unbind**，改为「按插件版本闭区间借用 → 拿到凭据 + 实际版本 → 直接按方法名或数字 ID 调用 → 主动或收到撤销通知后归还」。

## 1. 为什么迁移

v2 要求消费者先按 `contract`（`id`/`major`/`minor`）匹配，再用租约凭据 `bind_name`/`bind_id` 生成绑定、调用，最后 `unbind`。这套模型有两个问题：

- 绑定是一个额外的中间对象，消费者要同时管理凭据与绑定才能解绑/归还，回调路径容易漏掉某一步。
- 消费者需要额外管理协议 family 与契约版本，同时插件还有独立的发布版本；本轮选择直接用插件业务版本表达接受范围，减少一层公开概念。

v3 把它简化为：**版本范围 + 凭据**。插件版本就是类型化的 `plugin_version{major, minor, patch}`，消费者用显式闭区间表达接受范围；调用只凭凭据直接按名/ID 发起，不再创建绑定。

## 2. 兼容性边界（先读这一段）

- 现行入口是 `u42_get_factory`，宿主请求的 ABI 主版本是 `3`；`abi_major == 3`，命名空间 `u42::abi::v3`。项目版本为 `0.3.0`。
- 官方框架服务 `iid.high` 为 `0x3432555f41424933`（即 ABI v3），`iid.low` 仍为 1..5；`iid` 只命名框架服务，不再标识业务协议 family。
- **v1 与 v2 二进制被明确拒绝**：只支持主版本 `1` 或 `2` 的旧库对宿主的 `3` 请求返回 `unsupported`，不会加载。v3 不提供 v1/v2 的源兼容别名或同 `iid` 变签名，旧插件必须迁移源码后重新编译。
- 旧 `contract`/`protocol`/`binding`/`bind_name`/`bind_id`/`unbind` 在 v3 中**不存在**，既没有同名替代也没有保留别名。

## 3. 旧 / 新对照

| v2 的写法 | v3 的写法 |
| --- | --- |
| `plug_desc::version` 是 `const char*` 描述字符串 | `plug_desc::version` 是 `plugin_version{major, minor, patch}` |
| `contract{iid id, major, minor}` 业务协议 | `plugin_version` 由提供者承诺，`version_range` 表达接受范围 |
| `host::protocol(plug_id, &contract)` 发现协议 | `host::version(plug_id, &plugin_version)` 发现当前版本 |
| `icaps::acquire(plug_id, contract, revoker, &borrow)` | `icaps::acquire(plug_id, &version_range, revoker, &borrow)` |
| `icalls::bind_name/bind_id(credential, ...)` 生成绑定 | 直接用 `icalls::call_name/call_id(credential, ...)` |
| `icalls::call(binding, args, writer)` | `call_name(credential, name, args, writer)` / `call_id(credential, id, args, writer)` |
| `icalls::unbind(binding)` 只删绑定 | 已删除；只有 `icaps::release(credential)` 归还租约 |
| 归还后旧绑定 `stale` | 归还后旧凭据 `stale` |

## 4. 三步走：借用 → 调用 → 归还

下面是一个插件内部的分步示意：插件类实现 `irevoker` 且实例地址保持稳定，以下操作放在该类的成员函数中。省略了类定义与 `init()` 中取得宿主服务的样板；`caps_`、`calls_`、`lease_` 都是成员，不是全局变量。调用业务的片段只能在宿主将消费者置为 Active 后执行。

### 4.1 准备：固定写死你接受的版本闭区间

```cpp
#include <42u/sdk.hpp>

#include <cstdint>
#include <string>
#include <string_view>

namespace a = u42::abi::v3;

// 插件成员：init() 用 ictx::query 填充两个宿主服务指针。
a::icaps* caps_ = nullptr;
a::icalls* calls_ = nullptr;
u42::sdk::lease lease_; // 跨调用保存租约；on_revoke 使用同一个成员。

// 闭区间，两端都包含：接受 1.0.0 及以上的 1.x 全部版本。
// 跨 major（例如连 2.x 也接受）必须在这里显式写出，宿主不会自动扩展。
inline static constexpr a::version_range echo_versions{{1u, 0u, 0u}, {1u, UINT32_MAX, UINT32_MAX}};
```

### 4.2 第一步：借用，拿到凭据 + 实际版本

```cpp
if (lease_) return; // 已持有租约就复用，或先成功归还；不要重复借用后覆盖旧凭据。

a::borrow borrowed{};  // 输出：credential + 实际 version
const a::status acquired = caps_->acquire("com.example.echo", &echo_versions, this, &borrowed);

if (acquired != a::ok) {
    // 必须检查错误：
    //   unsupported      -> 提供者版本不在 echo_versions 内，未建立租约
    //   invalid_argument -> 范围无效（minimum > maximum）或必需指针为空
    //   其他             -> 状态 / 分配 / 线程错误（例如 wrong_thread）
    return;  // 失败时不要保存 borrowed：version 全零不代表成功
}

// 此前确认 lease_ 为空，成功后立即保存到成员，撤销回调才能找到并归还它。
lease_ = u42::sdk::lease(caps_, borrowed);
// ownership 由 credential 决定（非零），与 version 是否为 0.0.0 无关。
const a::plugin_version actual = lease_.version(); // 提供者真实版本，按值复制
```

`actual` 是宿主从实例描述**按值复制**的实际版本，不是你给的区间端点，也不是一段可能随库卸载而悬垂的库字符串。需要区分「1.2.0 与 1.9.0 行为不同」时，就用它选择处理逻辑。

### 4.3 第二步：凭据直接按名或 ID 调用

```cpp
std::string result;
u42::sdk::string_writer writer(&result, /*limit*/ 4096);
const a::bytes args = u42::sdk::view(std::string_view{"{\"hello\":\"42u\"}"});

const a::token credential = lease_.credential();
const a::status called = calls_->call_name(credential, "echo", args, &writer);
// 等价的数字形式：calls_->call_id(credential, 1u, args, &writer);
// 名称与 ID 走同一条调用实现，结果一致。

if (called != a::ok) {
    //   stale         -> 凭据已归还或已失效：不要复用它，重新 acquire
    //   not_found     -> 方法未披露（提供者没有这个方法）
    //   invalid_state -> 本插件还在 Initialized，只能保存租约，不能调用业务
    //   invalid_argument -> 参数、凭据或 writer 有问题
    // 宿主不转交失败调用的部分输出；调用方也不要把旧结果当成这次成功的结果。
    result.clear();
}
```

### 4.4 第三步：归还

```cpp
const a::status returned = lease_.reset(); // 内部调用 caps_->release，保持本地所有权同步。
//   ok / stale -> 归还可视为完成（stale 表示宿主已不再跟踪），SDK 清空凭据与版本
//   busy       -> 该租约仍有在途调用（含输出交付），保留凭据稍后重试
//   其他       -> 同样保留凭据重试，不要丢弃后伪造归还
```

## 5. 版本语义（只有两类公开版本）

v3 的公开版本信息只有两类，实例代次（generation）是宿主私有信息，不对外暴露：

- **插件业务版本** `plugin_version{major, minor, patch}`：提供者对公开数据与行为的兼容承诺。破坏性变化应升 `major`；`minor`/`patch` 承诺兼容。宿主只做数值比较，不推断语义。
- **框架 ABI 版本** `abi_major`（当前 `3`）：与插件业务版本互不换算。

`version_range` 的规则：

- 闭区间 `[minimum, maximum]`，**两端都包含**。
- 两端相等表示精确版本；`exact_version(actual)` 就是 `{actual, actual}`。
- `0.0.0` 是**合法版本**，不能当作失败标志；成功要靠状态码和凭据是否非零判断。
- `minimum > maximum` 是无效范围，借用返回 `invalid_argument`。
- 宿主只按调用方给出的**显式范围**筛选，不会自动推断或自动拒绝某个 `major`。
- `major` 是否跨版本兼容由**提供者承诺**；跨 `major` 只有在调用方明确把两端写成跨 `major` 的区间时才可能被包含（例如 `{{1,0,0},{2,UINT32_MAX,UINT32_MAX}}`）。
- **没有字符串范围解析**（例如 `">=1.2.0 <2.0.0"` 这种写法不存在），也不支持预发布或构建标签（如 `1.0.0-rc1`）。

## 6. 稳定 revoker 的生命周期

`icaps::acquire` 的第三个参数是撤销接收端 `irevoker*`。它必须在凭据被归还之前一直有效，宿主会在卸载提供者时回调它。

- 把 `irevoker` 放在**稳定对象**上（例如插件实例自身 `this`），不要用临时的、会被移动或销毁的 SDK `lease` 充当接收端。
- 收到 `on_revoke` 时，先按凭据匹配，再停业务、清本代 session/缓存，最后归还：

```cpp
void U42_CALL my_consumer::on_revoke(a::token credential) noexcept
{
    if (!lease_.matches(credential)) return;  // 无关或已归还的撤销，忽略
    // 1) 停止依赖该提供者的业务；2) 清除本代会话与缓存
    const a::status status = lease_.reset();  // 内部调用 icaps::release
    // ok / stale：lease_ 置空；busy 等：凭据与版本保留，稍后重试
    (void)status;
}
```

- 归还当时若返回 `busy`（在途调用或输出交付未结束），必须保留凭据并在后续通知或自己的 `stop()` 中重试；不能丢弃凭据假装已归还。
- 消费得越少越好：只有在确实需要跨调用保持状态时才长期持有租约，否则按需借用、用完立刻归还。

## 7. 重载：同版本也要重建

- 旧提供者被卸载后，**即使新实例声明完全相同的 `plugin_version`**，旧凭据也会 `stale`，绝不跟随新实例。
- 必须重新发现版本、重新 `acquire`，并重建自己的业务 session 与缓存。
- 不得对同一个仍有效的租约盲目重复 `acquire`；也不要把两次通知当作同一个实例。

## 8. 管理端与 CLI

- `42uhost` 的 CLI 语法不变：`--list` / `--call PLUG METHOD JSON` / `--call-id PLUG NUMBER JSON`。
- 每次调用前，CLI 先用 `host::version()` 发现提供者当前版本，再把 `exact_version(actual)` 交给一次性调用。
- 这只是**管理端对单次操作**给出的版本要求，**不代表普通消费者会自动接受未知版本**：长期消费者必须自己写死/维护接受的版本范围，并处理 `unsupported`。

## 9. 不要夸大 v3 的能力

- **未归还租约 / `stop()` 失败会保留锁**：卸载会被拒绝，无法证明静默的实例会被隔离，而不是被强行拆解。
- **在途调用期间 `release` 返回 `busy`**：租约保留，不伪造归还。
- **Initialized 不能调用业务**：Initialized 消费者可以保存租约，但 `call_name`/`call_id` 会返回 `invalid_state`。
- **回调中重入会被拒绝**：插件调用栈内 `unload()` 对已知 ID 返回 `deferred`，`shutdown()`/`add()`/`boot()`/`load()` 返回 `busy`，`start()` 返回 `invalid_state`。
- **内存不足只做尽力清理**：可能留下 Created 或隔离记录供重试、关停，不承诺所有失败都完成回滚。
- **同进程治理，不是安全沙箱**：不提供内存隔离、崩溃隔离、强制超时或强杀，不支持不可信插件；v1/v2 拒绝只对如实检查 ABI 主版本的合作插件有效。

## 10. 迁移检查清单

- [ ] 删除所有 `contract`/`protocol`/`binding`/`bind_name`/`bind_id`/`unbind` 用法。
- [ ] `plug_desc::version` 改成 `plugin_version` 字面量，不再填字符串。
- [ ] 把原来的协议匹配改成显式 `version_range` + `accepts_version`。
- [ ] `acquire` 传 `const version_range*` 与稳定 `irevoker*`，保存整个 `borrow`。
- [ ] 调用改为 `call_name`/`call_id(credential, ...)`，不再生成/管理绑定。
- [ ] 归还统一走 `release`（主动或 `on_revoke`），检查 `busy`/`stale`。
- [ ] 重载后重新借用并重建 session，不沿用旧凭据。
- [ ] 入口按主版本 `3` 协商，旧 `abi_major` 如实返回 `unsupported`。

## 11. 验证状态

本轮 GCC Debug、ASan（正常退出泄漏检测开启）、UBSan、Clang Release 均为 11/11 测试目标通过，跨编译器真实插件加载和 CLI 回归通过。版本闭区间、实际借用版本副本、凭据调用与归还、同版本重载后的旧凭据失效均有持久测试。
